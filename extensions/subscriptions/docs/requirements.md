# Folyn 文章订阅插件：第一版需求与页面交互

版本：v0.1 需求讨论稿  
日期：2026-10-17  
用途：产品评审、交互设计，以及交给 Codex 进行实现拆解。  
范围：描述用户需求、页面行为和验收要求；具体代码结构、数据库、解析库和插件 API 由后续结合仓库确定。

## 1. 产品目标与决策状态

让用户在 Folyn 的一个 Vault 内订阅博客和技术网站，发现新文章，通过统一的纯净阅读视图阅读和翻译，再把有价值的内容保存为可编辑的 Markdown 文档。

核心流程：添加来源 → 获取文章更新 → 阅读或双语阅读 → 收藏或保存到 Vault。

### 1.1 已确认的需求

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| C01 | 阅读与收集都需要 | 同时覆盖发现更新、阅读文章和保存文档 |
| C02 | 第一版聚焦文章订阅 | 来源为博客、技术网站及其文章列表页 |
| C03 | 各 Vault 独立订阅 | 订阅源、文章、阅读状态、缓存各自独立 |
| C04 | 默认纯净阅读视图 | 提供「查看原网页」入口 |
| C05 | 打开文章时下载并缓存 | 可针对单个订阅源开启自动下载全文 |
| C06 | 第一版支持没有 RSS 的网站 | 同时支持 RSS/Atom 与普通网站文章识别 |
| C07 | 自动识别＋必要时辅助配置 | 首次添加失败或不准确时，允许用户辅助完成配置 |
| C08 | 第一版包含全文翻译和双语对照 | 支持原文、译文、双语三种模式 |

下文涉及翻译触发、刷新频率、初次导入数量、已读判定、窄窗口行为等细节，均为基于以上决策补齐的建议默认值，并非用户逐项确认过的决定。文档中「应」表示这份草案的验收要求；已确认范围以本表为准。

### 1.2 本稿提出的建议默认值

| 项目 | 建议默认值 |
| --- | --- |
| 刷新范围 | Folyn 运行且当前 Vault 已打开时，刷新该 Vault；切换后暂停原 Vault 的后续调度 |
| 刷新频率 | 30 分钟，可改为手动、15 分钟、1 小时或 6 小时 |
| 启动补查 | 打开 Vault 时，若距离最近一次成功检查超过设定间隔，立即检查 |
| 首次导入 | 最近 20 篇可发现文章；实际不足时显示真实数量 |
| 历史文章 | 用户主动加载，显示“已加载数量”，不承诺完整网站历史 |
| 已读判定 | 正文成功展示并在前台停留 2 秒后标记；用户可关闭自动标记 |
| 翻译方式 | 手动切换模式时按需触发，逐段展示并缓存结果 |
| AI 配置 | 复用 Folyn 现有模型配置；语言和阅读偏好属于当前 Vault |
| 保存方式 | 用户点击保存，默认保存在当前 Vault 的可选目录；本稿不将自动归档列为首版验收项 |
| 系统通知 | 默认关闭；首版以插件入口未读数和列表提示表达更新 |
| 缓存清理 | 默认手动清理，收藏文章默认受到清理保护 |
| 原网页入口 | 优先复用 Folyn 可用的网页打开能力，未提供时使用系统默认浏览器 |
| 搜索范围 | 当前 Vault 内已获取的标题、来源、摘要和已缓存正文 |

## 2. 第一版交付范围

第一版完整交付以下能力。实现可以分阶段推进，但无 RSS 网站支持与翻译功能都属于第一版。

| 功能组 | 内容 |
| --- | --- |
| 订阅源管理 | 添加、预览识别结果、辅助配置、编辑、分组、暂停、重新识别、取消订阅 |
| 文章更新 | 自动或手动刷新、新文章发现、去重、刷新状态和错误反馈 |
| 文章管理 | 全部、未读、收藏、已保存视图；搜索、筛选、排序、批量已读 |
| 阅读 | 纯净排版、代码/图片/表格/公式、阅读位置、查看原网页 |
| 缓存与离线 | 打开时缓存、按源自动下载、正文和图片缓存状态、清理与重新获取 |
| 翻译 | 原文、中文译文、逐段双语；模型配置复用、长文进度、结果缓存和失败重试 |
| 保存 | 保存原文、译文或双语为 Markdown；来源信息、附件处理和重复保存保护 |
| Vault 隔离 | 数据、辅助配置、阅读状态、缓存和异步任务结果均绑定所属 Vault |

页面内容变化监控、邮件 Newsletter、播客、跨设备同步、AI 摘要、自动归档、文章高亮批注和推荐算法可以另行讨论，本稿不为它们设置第一版验收项。首次上线的站点覆盖以“明确支持的页面类型＋真实站点验证”描述，避免用“支持没有 RSS”暗示任何网页都能自动订阅成功。

## 3. 用户场景

| 场景 | 用户期望 | 成功结果 |
| --- | --- | --- |
| 关注技术博客 | 输入 claude.dev 这类网站地址，及时看到新文章 | 来源识别正确，文章更新进入当前 Vault 的收件箱 |
| 订阅普通网站 | 网站没有 RSS，也能跟踪文章列表 | 自动识别或经过一次辅助配置后持续检查更新 |
| 英文技术阅读 | 阅读英文原文，必要时查看中文解释 | 可切换译文或双语，并保留代码与术语上下文 |
| 长期积累 | 保存有价值的文章并继续编辑 | 生成普通 Markdown 文件，包含来源，可在 Folyn 编辑器打开 |
| 离线阅读 | 出门前缓存想看的文章 | 缓存完整度明确，离线时可以读取已有正文及已缓存资源 |
| 工作与个人分开 | 不同 Vault 关注不同来源 | 两个 Vault 的订阅、未读数、收藏和阅读位置互不影响 |

## 4. 入口与信息架构

插件以工具工作区形式进入 Folyn。建议在现有 Activity Bar 中提供「订阅」入口，点击后在当前 Vault 中打开订阅工作区。具体入口接入方式应服从现有插件能力。

插件入口显示当前 Vault 的未读数；没有打开 Vault 时，显示「打开一个 Vault 后开始订阅」及现有打开 Vault 操作。插件安装可由 Folyn 统一管理，其用户数据和配置仍按 Vault 隔离。

页面清单：

| 页面编号 | 页面/浮层 | 职责 |
| --- | --- | --- |
| P01 | 订阅工作区 | 来源导航、文章列表、正文阅读 |
| P02 | 添加订阅浮层 | 输入网址、识别、预览、确认 |
| P03 | 辅助配置面板 | 纠正文章列表、示例文章与正文范围 |
| P04 | 订阅源设置面板 | 名称、分组、刷新、下载、暂停及重新识别 |
| P05 | 保存到 Vault 浮层 | 内容形式、目录、文件名、附件与重复处理 |
| P06 | 插件设置面板 | 当前 Vault 的阅读、翻译、缓存和刷新默认值 |
| P07 | 取消订阅/清理缓存确认框 | 明确影响范围并执行可理解的清理 |

## 5. P01：订阅工作区布局

### 5.1 三栏结构

| 区域 | 建议宽度 | 内容 | 主要交互 |
| --- | --- | --- | --- |
| 左侧导航 | 默认 220px，可折叠和拖动 | 添加订阅、系统视图、分组和来源、设置 | 切换来源、查看数量、来源菜单、移动分组 |
| 中间文章列表 | 默认 320px，可拖动 | 视图标题、搜索、筛选、文章条目、加载更多 | 选择文章、多选、批量已读、切换排序 |
| 右侧阅读区 | 占剩余宽度，正文建议最大宽度 760px | 文章头部、阅读工具、正文、加载与翻译状态 | 阅读、切换语言、收藏、保存、查看原网页 |

宽度为布局起点，后续按 Folyn 现有字号和边距校准。正文区应保持适合阅读的行宽，不随窗口无限拉宽。表格和代码块可在自己的区域横向滚动。

建议布局适配：内容工作区不足 1100px 时左栏默认折叠；不足 800px 时文章列表与正文切换显示，正文顶部提供「返回列表」。以实际可用内容宽度判断，不能仅根据整窗宽度推断。

折叠、展开和拖动时保持当前文章与阅读位置。阅读区应能独立滚动，切换文章不改变左侧导航位置。

### 5.2 左侧导航

建议系统视图顺序为：全部文章、未读、收藏、已保存；其下显示用户分组和订阅源。

- 来源行显示图标、名称、未读数量；悬停或键盘聚焦时出现菜单入口。
- 分组支持创建、重命名、折叠及移动来源；删除分组时来源移入「未分组」，不删除来源。
- 来源菜单包含：立即刷新、编辑订阅、移动分组、暂停/恢复、重新识别、取消订阅。
- 来源状态包括正常、刷新中、已暂停、需要处理。状态不能只用颜色表达。
- 选择来源时仅筛选文章；文章列表与阅读区继续使用同一套交互。

### 5.3 文章列表

单条文章展示标题、来源、发布时间或发现时间、简短摘要，以及未读、收藏、已保存、离线可用等状态。摘要缺失时不强制调用 AI 生成，不把正文尚未获取显示成抓取失败。

默认最新在前：有可信发布时间时优先使用发布时间；缺失时使用首次发现时间，并明确显示「发现于」。不能把发现时间伪装成发布时间。

- 单击选中文章并开始加载正文；收藏和已读按钮点击时不误触文章切换。
- 当前文章已读后，应在当前未读列表中暂时保留，避免阅读中条目消失；切换筛选或重新进入视图时再更新列表成员。
- 搜索输入保留当前视图范围，可清空；离线时搜索已有数据。
- 全文搜索仅覆盖已缓存正文；搜索结果旁提示搜索范围，避免给出“全站无结果”的暗示。
- 批量「标为已读」默认作用于已选条目；「全部标为已读」显示来源/视图范围和数量后确认。
- 新文章到达时更新未读数，并显示「有 N 篇新文章」入口；不强制插入到当前滚动位置。
- 列表采用渐进加载或分页，保持选择状态，避免一次渲染大量文章。

### 5.4 阅读工具栏与文章头部

文章头部显示标题、作者（如有）、来源、发布时间（如有）和阅读状态。内容缺失时自然省略相应字段。

建议主要操作顺序为：原文/译文/双语切换、收藏、保存到 Vault；查看原网页与更多菜单保留稳定入口。更多菜单包含标为未读、重新获取正文、复制来源链接、清理本文缓存。

「查看原网页」打开文章的来源链接。阅读模式切换保留当前语义段落位置，避免从正文中部跳回开头；无法精确对应时定位到最近的原文内容块。

键盘可以完成视图切换、列表选择、打开文章、工具栏操作和退出浮层。沿用 Folyn 全局快捷键规范；本稿不指定可能冲突的新组合键。

## 6. P02 / P03：添加订阅与辅助配置

### 6.1 自动识别流程

~~~mermaid
flowchart TD
    A["输入网站地址"] --> B["发现订阅源或识别文章列表"]
    B --> C{"识别结果是否可信"}
    C -->|"是"| D["预览来源与文章"]
    C -->|"否"| E["辅助配置"]
    E --> D
    D --> F{"用户确认结果"}
    F -->|"需修正"| E
    F -->|"正确"| G["创建订阅并导入首批文章"]
~~~

添加浮层第一步只有网址输入和「识别」按钮，支持网站首页、文章列表页、RSS/Atom 地址。粘贴单篇文章地址时，尝试找到所属列表；无法确定时提示用户补充列表地址。

识别期间展示「正在查找订阅源」「正在识别文章列表」等有明确含义的进度。支持取消；取消前不创建半成品订阅。

识别成功后展示：

| 信息 | 行为 |
| --- | --- |
| 来源名称、网站地址 | 自动填入，可编辑显示名称 |
| 获取方式 | 显示「标准订阅源」或「网站识别」，无需理解技术术语即可继续 |
| 多个候选列表/订阅源 | 展示名称和几篇样例，让用户选择需要的范围 |
| 文章预览 | 5～10 篇标题、链接及可获得的发布时间；展示实际条目，不生成示例内容 |
| 正文预览 | 展示至少一篇样例的正文提取结果，判断是否误选评论、导航或摘要 |
| 分组和刷新设置 | 默认「未分组」、30 分钟，可修改 |
| 自动下载全文 | 默认关闭，说明开启后会为后续发现的文章下载正文和可缓存资源 |
| 首次导入范围 | 默认最近 20 篇可发现文章，可在首次确认前调整 |

确认按钮显示「订阅并导入」。订阅成功后关闭浮层、选中该来源，显示实际导入数量。识别过程抓取的样例正文可以直接复用为缓存。

同一 Vault 内再次添加相同来源时，提示「已订阅」并提供跳转已有来源；不同 Vault 允许独立添加。一个站点的不同分类列表可以分别订阅。

### 6.2 没有 RSS 的网站

目标是跟踪页面中的文章条目，识别新增文章及其链接。应覆盖已明确支持的普通静态列表和通过常见动态加载方式展示的文章列表。分页、「加载更多」、日期缺失等情况应有可见支持状态；不支持时进入辅助配置或明确说明。

识别范围应围绕用户确认的文章列表，避免把整站导航、视频模块、产品页和外链推荐全部导入。刷新时支持回溯若干列表页，回溯范围和历史边界可展示；长时间未打开 Folyn 后如无法补齐全部文章，应提示覆盖范围。

网站发生变化时需要检查识别结果合理性，例如原本能识别的列表突然为空、样例正文仅剩导航、跳转到登录页。只有可验证的识别异常才标记需要处理；正常空列表可以视为无新文章。可疑结果不应直接覆盖已缓存的正文。

### 6.3 辅助配置流程

辅助配置优先使用普通用户能提供的信息：

1. 确认或修改文章列表地址。
2. 从候选文章中选择正确条目，或粘贴一篇示例文章链接。
3. 如存在多种列表，选择实际需要跟踪的列表。
4. 核对正文预览；不正确时补充正确示例或选择可用的正文范围。
5. 点击「测试识别」，展示匹配到的文章和正文，再保存配置。

辅助配置优先通过候选预览完成；若使用页面区域选择，应有可操作的页面预览。不能只提供一个要求用户填写 CSS 选择器的表单并视为完成此需求。

需要同时验证“能找到文章”和“能提取正文”。原始示例页面发生变化时，用户仍能更换示例，重新测试；新配置验证成功后才替换旧配置。

如当前站点仍无法识别，保留输入和配置草稿，提供重试、更换列表地址、查看原网页等操作；不创建看似成功但无法获取文章的订阅。不默认承诺付费正文或登录后内容可自动获取。

## 7. 文章刷新、身份与阅读状态

### 7.1 刷新行为

按当前 Vault 的刷新规则运行。用户可刷新单个来源或当前 Vault 的全部来源；刷新中可继续阅读已有文章。

来源页显示「最近成功检查时间」与本次状态；失败尝试不能覆盖最近成功时间。全部来源刷新时按源展示结果，一处失败不应让其他来源的成功结果丢失。

Folyn 退出或 Vault 关闭后不继续承诺后台刷新。恢复运行后补查站点当前可发现的文章；连续历史覆盖受来源的分页和保留范围限制。

### 7.2 文章身份与去重

优先使用来源提供的稳定文章标识和规范化原文地址。重定向、明确的跟踪参数与片段锚点不应轻易生成重复条目；会影响文章身份的查询参数必须保留。不能仅凭相同标题合并文章。

同一文章出现在当前 Vault 的多个来源时，可以保留多个来源归属，共用文章内容与阅读状态；取消一个来源不能删除仍被其他来源引用的文章。不同 Vault 的同一文章保持独立。

标题或发布日期更正时更新列表元信息，保留收藏、已读和保存关系。正文更新应提示「原文可能已更新」，由用户选择重新获取；不能静默覆盖正在阅读或已经编辑的正式文档。

### 7.3 已读、收藏与阅读位置

- 已读、收藏、已保存互相独立，缓存成功或翻译成功不能自动等价为已读。
- 自动已读只在正文成功展示且前台停留达到阈值后触发；加载失败、后台预加载和仅经过列表时不触发。
- 用户手动标为未读后，本次阅读不立刻重新自动标为已读；再次打开时恢复正常判定。
- 收藏不会自动在 Vault 中创建文件，也不会自动触发 AI 请求。
- 阅读位置按文章和阅读模式保存；恢复到对应内容块，并允许回到顶部。

## 8. 纯净阅读与缓存

### 8.1 正文质量要求

正文提取应保留标题层级、段落、列表、引用、强调、链接、图片及说明、代码块及可得语言信息、表格和公式。过滤导航、推荐列表、广告、订阅弹窗和评论区等非正文。

技术内容不能因统一排版而改变语义。代码与表格独立横向滚动；正文链接支持原有访问方式，图片可查看大图。原站依赖脚本的图表或交互内容应保留可用的静态替代，无法展示时提供原文位置或原网页入口，不能悄悄丢失。

文章内容作为受控阅读内容展示，移除可执行脚本和事件处理；正文链接不能取得插件权限。阅读排版沿用 Folyn 主题，中文与英文自然左对齐，不默认使用强制两端对齐。

### 8.2 获取与离线状态

打开文章时按已有可用正文、订阅源全文、文章页提取的顺序复用或获取。只有摘要时明确显示摘要，不把它标为完整正文。

| 状态 | 展示与操作 |
| --- | --- |
| 尚未缓存 | 打开时获取，列表可显示元信息 |
| 获取中 | 展示骨架和获取状态，可以切换文章 |
| 正文已缓存，资源处理中 | 可先阅读正文，同时显示图片下载进度 |
| 离线完整可用 | 正文及受支持的必要资源已成功缓存 |
| 部分离线可用 | 显示缺失图片或动态内容提示，联网后可重试 |
| 无缓存且离线 | 提示「联网后可获取正文」，保留文章元信息与收藏操作 |
| 提取不完整 | 明确提示，可重试、重新配置或查看原网页 |

已读缓存文章默认离线可打开。仅缓存正文不能宣称图片、视频和所有嵌入内容均离线可用。为受支持图片设置合理的资源和空间限制，达到限制时显示缓存完整度。

对来源开启自动下载时，默认作用于随后新发现的文章；现有文章提供独立的「下载现有文章」动作，先显示数量，再加入队列。逐篇展示结果，个别失败可重试。

### 8.3 清理与重新获取

缓存空间在当前 Vault 的插件设置中展示，允许清理选定文章、按来源清理或清理全部可清理缓存。清理确认框明确列出正文、图片、翻译结果的影响；翻译缓存可单独选择是否清除。

保留文章元信息、已读、收藏和保存关系。默认保护收藏文章；若用户选择同时清理收藏缓存，需要显式勾选。清理后的文章可以重新获取。已生成的 Markdown 和其保存附件不属于插件缓存。

重新获取正文成功后才替换旧缓存；失败时仍可读取旧版本。源正文变化后，相关翻译标记为旧版本并允许更新。

## 9. 全文翻译与双语阅读

### 9.1 模式与触发

阅读工具栏提供「原文 / 译文 / 双语」三个等价模式，原文始终可以访问。默认原文；后续可在当前 Vault 设置中记住用户偏好。翻译默认目标语言为简体中文。

首次切换到需要译文的模式时触发翻译，已有有效缓存则直接展示。没有可用 AI 配置时，显示设置入口并保留原文阅读。首次调用前明确使用的模型和将发送的文章内容范围；不自动把整个 Vault 发送给模型。

同一篇文章重复切换模式不会重复创建相同翻译任务。已开始的翻译可在用户切换文章后继续并缓存；提供取消入口。关闭 Vault 时停止为其启动新任务，迟到结果仅写回所属 Vault。

### 9.2 翻译质量与排版

- 以正文内容块建立原文和译文对应关系，保留段落、标题、列表及引用层级。
- 双语采用「原文内容块＋对应译文」上下排列，不要求用户同时进行左右两栏阅读。
- 代码块、命令、标识符、公式和链接目标保留原样，翻译周围解释文字；代码中的注释不默认修改。
- 表格翻译自然语言单元格，保持行列对应；图片只展示一份，双语说明紧邻图片。
- 常见技术专有名词保留英文，必要时附中文说明，避免把产品名或 API 名改写成另一含义。
- 只展示已有原文对应的翻译，避免生成不存在的段落或省略原文内容。
- 纯中文文章切换译文时提示「本文无需翻译」，避免无意义调用；混合内容可只翻译需要翻译的部分。

### 9.3 长文、进度与失败

显示总内容块、已完成数量、失败数量和取消操作，译文可以逐步出现。未完成部分保留原文和状态，不用空白代替。

按模型可承受的长度分段，要求覆盖全文；不能只翻译开头却标记全文完成。某段失败支持单独重试，保留成功部分。取消后保留已完成缓存，并可继续处理剩余内容。

翻译结果关联原文版本、目标语言及所用模型信息。切换模型配置不会自动覆盖现有译文；用户可以主动重新翻译，已有结果在新结果成功前仍可查看。

译文或双语尚未完成时，保存浮层应显示完整度，并提供等待完成、保存已完成部分（明确含原文回退）或仅保存原文的选择。

## 10. P05：保存到 Vault

### 10.1 保存流程

点击「保存到 Vault」后展示：

| 字段 | 默认与交互 |
| --- | --- |
| 内容形式 | 原文、译文、双语；默认跟随当前阅读模式 |
| 目标目录 | 当前 Vault 内上次使用的有效目录，首次使用时选择目录 |
| 文件名 | 根据标题生成，自动处理非法字符，并允许编辑 |
| 附件 | 默认保存可获取的正文图片为本地附件，列出数量和缺失项 |
| 来源信息 | 默认保留标题、作者、来源、原文地址、发布时间（如有）、保存时间 |
| 保存完成后 | 提供「打开文档」；留在阅读页时保留阅读位置 |

保存按钮显示进行中，避免连续点击生成多个相同文件。写入失败时保留浮层输入和已完成内容，提供重试。

示例元信息仅用于说明字段，不要求实现采用固定代码结构：

~~~yaml
---
title: "示例技术文章"
source_url: "https://example.com/blog/sample"
source_name: "示例技术博客"
author: "示例作者"
published_at: "2026-10-01"
saved_at: "2026-10-17T10:20:00+08:00"
content_mode: "bilingual"
translated_to: "zh-CN"
---
~~~

缺失字段应省略或保持明确空值，不编造作者、日期或阅读时长。元信息格式应适配 Folyn 已有文档约定；多作者和正文来源变化需要能够表达。

### 10.2 内容与附件要求

保存后的文件可以离开订阅插件单独阅读和编辑，图片使用正式保存附件的本地相对路径。图片不能引用随缓存清理而消失的位置。

部分附件无法下载时显示清单，用户可重试或选择保留远程链接后继续；不能在仍有远程依赖时宣称完全离线保存。无法可靠转换的交互图表保留静态替代或明确的原文链接。

译文与双语保存保留翻译说明、目标语言及来源，便于区分原作者内容与机器译文。文件写入、附件完成情况和保存关系保持一致；未完成写入时不能标记「已保存」。

### 10.3 重复保存与文档保护

同一 Vault 中再次保存同一文章、同一内容形式时，默认提示已有文件，并提供「打开已有文档」与「另存副本」。不同内容形式允许另存，并使用可辨识文件名。

文章列表中的「已保存」标识可打开关联文件；一篇文章允许关联原文、译文等多个文件。文档重命名或移动后尽可能通过 Folyn 文件生命周期事件更新关系。

若文件已删除，显示「保存文件已移除」并允许重新保存。缓存正文刷新、重新翻译、取消订阅和重新订阅均不得自动覆盖用户编辑过的 Markdown 文件。

## 11. P04 / P06：来源设置与插件设置

### 11.1 来源设置

包括名称、网站/列表地址、所属分组、刷新间隔、自动下载全文、最近成功时间、来源状态、辅助识别配置及测试入口。

修改显示名称和分组立即生效；修改列表地址或识别方式需要先测试。地址变化后保留已有文章及状态，再按照新来源发现更新。

暂停来源停止自动刷新和自动下载，已有文章继续可读；用户点击手动刷新时明确提示正在检查暂停的来源，检查结束后仍维持暂停状态。

### 11.2 取消订阅

取消订阅前说明作用于当前 Vault，并提供默认勾选的「保留收藏文章」与「保留已保存文档的文章记录」选项。其他仅由该来源引用的文章和缓存可随确认移除。

存在其他来源归属的文章继续保留。被保留但失去来源的文章进入当前 Vault 的「保留文章」分组，仍能访问缓存及来源链接。只提供已勾选保留项的数量，不制造无法理解的数据残留。

正式 Markdown 与其附件始终通过文件管理能力维护，取消订阅不删除它们。再次订阅时，对仍保留的文章恢复来源关联并保留原有状态。

### 11.3 当前 Vault 的设置

提供默认刷新间隔、已读判定、默认阅读模式、目标语言、AI 配置入口、默认保存目录及缓存管理。

清楚区分当前 Vault 的偏好与 Folyn 共享的模型配置。不得因修改一个 Vault 的目标语言而修改其他 Vault 的阅读偏好。

卸载或禁用插件时停止调度；若提供清除插件数据，应单独明确作用范围，保留由用户保存的 Markdown 文档及附件。

## 12. Vault 切换与任务行为

每个来源、文章、辅助配置、正文/图片/翻译缓存、阅读位置和保存关系都属于一个确定的 Vault。

建议切换时：

1. 保存原 Vault 的视图、筛选和阅读位置，停止为其调度新任务。
2. 取消可取消的获取或翻译任务；已发出的请求返回时核对所属 Vault。
3. 新 Vault 只读取自己的来源和文章，按自己的刷新间隔决定是否补查。
4. 原任务迟到结果不得出现在新 Vault 的列表，也不得写入新 Vault 的缓存或文件。
5. 再次打开原 Vault 时恢复自己的阅读上下文。

保存浮层打开时切换 Vault，应关闭原浮层并保留其草稿；用户回到原 Vault 后可恢复。已开始的文件保存只能完成到原 Vault，不能跟随当前界面切换目标。

任务、缓存和元信息应能从所属 Vault 的持久化数据恢复。具体存储位置、与 Vault 备份的配合、凭据存储方式由实现设计确定；不因本稿涉及本地优先而隐含跨设备同步保证。

| 场景 | 页面反馈示例 | 可执行操作 |
| --- | --- | --- |
| 未打开 Vault | 打开一个 Vault 后开始订阅 | 打开 Vault |
| 尚无来源 | 订阅你关注的博客和技术网站 | 添加订阅 |

| 来源识别疑似失效 | 网站结构可能已变化，需要重新确认识别范围 | 测试并重新配置 |
| 刷新失败 | 本次检查失败，上次成功检查于…… | 重试、查看原因 |

错误提示区分获取失败、解析失败和没有新文章。取消操作不显示为失败。常规操作以局部反馈为主，避免频繁打断阅读。

## 14. 交互状态约束

来源、正文、翻译与保存状态分别表达，不能用一个统一的成功/失败状态混淆它们。

| 对象 | 主要状态 | 不应发生的混淆 |
| --- | --- | --- |
| 来源 | 正常、刷新中、暂停、需处理 | 正文失败不必然表示来源列表失效 |
| 正文 | 未缓存、获取中、可读、部分、失败 | 有摘要不等于全文成功 |
| 翻译 | 未开始、进行中、部分、完成、失败、已取消、旧版本 | 一个段落成功不等于全文完成 |
| 保存 | 未保存、保存中、已保存、部分资源待处理、失败、关联文件移除 | 收藏和缓存不等于正式保存 |
| 阅读 | 未读、已读；另有阅读位置 | 自动下载不等于用户读过 |

连续快速切换文章时，只让当前文章的结果更新当前阅读区；其他结果可回写各自缓存。重复点击刷新、下载或翻译应复用或明确排队，避免相同任务重复运行。

| A21 | 打开时缓存 | 首次获取后可离线重开，失败不误标全文成功 |

| A34 | 保存错误恢复 | 目录失效、空间不足等失败可恢复，未完成时不误标已保存 |
| A35 | 取消订阅 | 保留项、其他来源归属和正式文档符合提示 |
| A36 | Vault 隔离 | 同一来源在两个 Vault 中的未读、收藏、缓存与配置独立 |
| A37 | 异步切换 | 获取、翻译、保存过程中切换 Vault，不发生数据串写 |
| A38 | 重启恢复 | 当前 Vault 的来源、状态、缓存及阅读位置正常恢复 |
| A39 | 键盘操作 | 键盘能完成添加、选文、阅读工具栏与浮层操作 |
| A40 | 批量刷新 | 某个来源失败时其他成功结果和原有阅读上下文保留 |

首个真实站点建议使用用户提供的 https://claude.dev/，验收“输入网址、确认文章、纯净阅读、翻译、保存”的完整流程。它只作为真实体验样例，不预设其具体订阅格式；无 RSS 能力另用明确没有订阅源的静态与动态样例验证，不能用 RSS 路径冒充完成。

## 16. 建议实施顺序与交接说明

## 17. 仍需在实现前核对的能力

以下属于技术核对，不需要用户重新确认已经做过的产品选择：

- Folyn 当前是否提供可复用的动态网页获取与安全阅读渲染能力。
- 现有插件是否能监听 Vault 关闭、切换、文件重命名和删除事件。
- AI 接口是否支持流式结果、取消、重试及长文分段。
- 当前 Vault 是否支持把图片等附件保存为稳定的相对路径。
- 来源识别规则、缓存和状态采用何种持久化方式，如何随 Vault 备份和迁移。
- 提取结果质量判定、动态列表加载和历史回溯的具体支持边界。

以上核对结果用于确定实现方式；如果需要缩减 C01～C08 中已经确认的能力，应提出具体影响后再讨论。
