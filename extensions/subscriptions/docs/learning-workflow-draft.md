# Folyn 订阅学习能力：场景与交互讨论稿

版本：v0.3  
日期：2026-10-19  
状态：用户已选定A「并排伴读」，0.4.0正式插件已实现下述首期链路。测试、浏览器验证及原生验收边界见[验收记录](learning-acceptance.md)。B/C仅为历史原型。

已确认方向：围绕「读懂、联系、应用」三个场景，采用A「并排伴读」，利用Folyn的对话、编辑器与Vault能力，让阅读过程中产生的理解和实践得到记录。用户选择的是A，B/C保留为历史对比原型，不作为三个必需界面一同实现。下文的交互细节、组织方式与首期范围是围绕A提出的实施建议。

## 1. 一个贯穿的例子

用户正在读《异步任务的取消与资源清理》，想解决「切换Vault后，图片下载任务应该怎样处理」。

| 场景 | 用户动作 | Folyn参与 | 留下的内容 |
| --- | --- | --- | --- |
| 读懂 | 选中一段，问「取消请求后，为什么还可能继续写文件？」 | 带着引文与文章上下文解释、举例；需要时生成可编辑的机制图 | 原文依据、自己的理解、未解决的问题 |
| 联系 | 加入已有的《图片缓存方案》笔记，问「我的方案遗漏了什么？」 | 对照材料的前提、补充之处与分歧，指出相应依据 | 「原方案需要补充写入前的任务归属检查」及两份材料的引用 |
| 应用 | 写下「测试切换Vault后是否产生迟到写入」 | 协助整理实验步骤、预期现象与验证条件 | 实验结果、实际限制、修正后的结论 |

用户可以只记一句想法、只讨论一个疑问，或直接开始实践。三个场景可以往返，也可以跳过。

## 2. 建议的组织方式

### 2.1 以问题串起学习

建议围绕一个问题或目标保留一份「学习记录」，关联讨论、材料、草稿与正式笔记。标题可以从第一条问题或想法生成，开始时无需填写表单。

- 同一篇文章可以产生几个不同问题。
- 同一个问题可以引用多篇文章与多份已有笔记。
- 用户可从文章继续此前的记录，也可开始一个新问题。
- 仅浏览文章不创建空记录、不发起AI请求。
- 「已读」继续表示阅读状态；理解和验证通过用户留下的内容表达。

这里的学习记录是组织信息的建议名称，不意味着新增一个常驻工作区或独立文件格式。

### 2.2 内容及其归属

| 内容 | 用户看到什么 | 保存与修改方式 |
| --- | --- | --- |
| 原文引用 | 引句、文章标题、出处，支持回到来源 | 保留引用快照及版本；用户修改自己的想法不会改变原文 |
| AI讨论 | 用户提问与AI回答，能查看本次使用的材料 | 复用宿主模型配置与流式调用；插件保存讨论，回答由用户选择后进入笔记草稿 |
| 我的想法 | 用户可以随时直接写下的正文 | 自动保存为可恢复草稿；AI整理先提供建议稿，保留用户原话 |
| 正式笔记 | 当前Vault中普通、可编辑的Markdown文件 | 新建，或把选定内容加入已有笔记；可在Folyn编辑器继续修改 |
| 实践结果 | 尝试的步骤、观察与结论 | 补在相同记录或关联笔记里，保留原问题与出处 |

保存原文继续作为资料归档能力。学习笔记可以只含一条判断与一处引用，不要求固定模板，也不要求保存整篇原文。

## 3. 入口与使用过程

### 3.1 阅读时进入

默认保持现有三栏和阅读工具条的密度。文章工具条提供一个「学习」入口，按需打开相关记录和宿主对话；已有记录时优先提供继续入口。

划选正文后提供两个动作：

- **追问**：把选中的引文放入输入区，用户输入问题后发送。读懂、联系、应用以可编辑的提问建议展开。
- **记想法**：带着引文打开短草稿，用户可直接写下自己的想法。

未划选时也可以追问整篇文章或直接记想法。选择材料、打开入口和编辑提示词本身不发起模型请求，发送问题或明确选择生成动作时再调用。

采用A的右侧按需面板，包含「追问」「我的想法」两个标签。读懂、联系、应用放在追问中的可编辑提问建议区。切标签不清空讨论和草稿，「我的想法」可以直接输入，无需先问AI。

宽窗口保持原文与面板同时可见，面板通过栏间分隔线调整宽度并记忆。空间不足时沿用现有来源栏/列表收展，再以按需学习面板呈现，保留阅读位置；关闭后恢复阅读和焦点。布局、控件高度、明暗主题沿用现有密度，不在来源树插入学习条目。

讨论绑定学习记录。阅读从文章A切到B时，面板仍显示正在讨论的来源与材料；明确选择「加入当前讨论」或新开问题，B才进入上下文。对话和草稿不会因阅读切换而清空，迟到回复继续归原记录。

### 3.2 读懂：让疑问可持续追问

1. 选中的引文作为可回看的来源条目进入讨论，原文仍可阅读。
2. 输入区展示当前使用的文章与附加材料，用户可以移除或补充。
3. 解释流式返回，可继续追问「举个例子」「解释这个前提」「用图表示」。
4. 用户可随时写下自己的理解，也可主动请AI检查复述中的遗漏。
5. 文章依据可定位到出处；AI推演和外部补充需要与原文观点区分。

长文章超过模型上下文范围时，展示本次实际使用的范围，并允许补充材料。切换阅读文章不会悄悄替换已有讨论中的材料；用户通过「加入讨论」明确加入另一篇文章。

### 3.3 联系：围绕真实材料建立关系

1. 用户从当前Vault选择已有笔记，或选择另一篇订阅文章，加入当前讨论。
2. 输入自己的联系问题，例如「这和我以前的理解有什么差别？」。
3. AI对照各份材料，说明补充、分歧和适用前提，并附上相应引用。
4. 用户选择有价值的结论，补入草稿或已有笔记。

首期建议以主动选材料完成这个场景。相关笔记推荐可以后续探索；宿主当前有文本搜索，尚无可供插件直接复用的笔记语义检索能力。

### 3.4 应用：让实践结果回到原问题

1. 用户说明使用目标、限制和预期结果。
2. 讨论产出适合该目标的实验、方案或步骤；用户可以直接编辑。
3. 实际尝试后，补充观察、证据与结果。
4. 根据结果修正原有理解，并更新关联笔记。

技术文章可以产出代码实验、测试条件或设计修改；其他文章也可以产出一次决策、写作提纲或工作方法的尝试。第一步由用户明确需求决定，不为每篇文章自动创建任务、提醒或测验。

## 4. 记录与整理到笔记

### 4.1 随手记录

草稿可单独存在，也可关联一段对话。用户输入自动保存，保存状态可见；失败时保留输入并提供重试。切换文章、关闭面板和重启后可以继续。

选取AI回答时保留来源标识；选择「整理成笔记」后先展示可编辑草稿。用户自己的文字、原文引用和AI建议保留可辨认的归属，不通过复制整段聊天强迫用户重新清理。

### 4.2 写入Vault

「整理到笔记」提供新建和选择已有笔记两个去向，优先列出本次记录已经关联的笔记。

- 新建：可调整标题、目录和正文，确认保存为Markdown后在编辑器打开。
- 已有笔记：展示目标、插入位置及将加入的内容，保留编辑器未保存修改，并支持撤销。
- 草稿允许长期保留，不要求每次讨论都生成文件。
- 文件重命名后继续维护关联；目标不可用时保留草稿并允许重新选择。

已有笔记的插入流程需由宿主编辑器衔接保证，不能直接用磁盘旧内容覆盖正在编辑的文档。

### 4.3 回看与来源保护

从文章可以看到相关问题、草稿和笔记；从笔记中的引用可以回到原文章。引用保留文章标题、URL、引句与正文版本，不依赖临时DOM编号。

译文引用保留其语言与译文版本；可以可靠匹配原文时提供对照。文章更新后无法定位引句时仍显示原引用，并说明位置已变化。清缓存或取消订阅保留学习记录、引用快照和正式笔记。

## 5. 建议先验证的一段完整体验

在同一个问题下完成：

1. 选中一段原文，开始多轮追问，返回后还能继续。
2. 不调用AI，直接记下一句自己的理解，关闭再打开仍在。
3. 主动加入一份已有笔记，对照前提与差异。
4. 将选定的引用、想法或AI内容整理成可编辑草稿。
5. 新建笔记或补入已有笔记，打开后继续编辑；从引用能返回文章。
6. 写下一次应用尝试，再补充结果，修正原来的判断。

这是0.4.0的首期实现范围。浏览器使用模拟AI和内存Vault；真实模型效果和完整原生安装仍需单独验收。

## 6. Folyn能力与0.4.0衔接

| 需求 | 当前基础 | 0.4.0处理 |
| --- | --- | --- |
| 基于文章的流式追问 | 扩展ai.chat支持sessionId、流式、多轮、模型选择 | 独立伴读面板；显式发送带来源的材料和历史 |
| 返回后继续讨论 | 宿主已有会话及AI面板 | 插件持久化讨论；每次调用使用独立ID与persistHistory:false，不依赖会新建会话的useSharedSession |
| 选择已有笔记 | 宿主文件与Markdown搜索；扩展可读已知路径 | 原生多选Markdown文件及材料快照交接；首期不做自动推荐 |
| 新建笔记并打开 | 固定Vault会话的createText、readText、open | 已实现可恢复草稿与来源/笔记关联 |
| 补进已有笔记 | 宿主编辑器与文件能力 | 已实现未保存内容保护、文末预览、单笔撤销和双重快照冲突检查 |
| 图解与实践 | 宿主支持Markdown图表和Agent产品模式 | 按需交接到宿主产品；扩展ai.agent当前明确拒绝调用，首期学习流程不依赖它 |

对话、草稿、文件和迟到的模型结果均需绑定开始时的Vault与学习记录。插件的学习数据保存问题、引文快照、用户草稿正文、恢复所需信息与关联关系，并与可清理的文章/译文缓存隔离。宿主管理模型配置、凭据与传输；插件调用ai.chat时设置persistHistory:false，显式发送当前记录的有界材料和历史，避免共享会话串上下文。正式笔记继续使用普通Vault文件。

## 7. A的首期实施顺序

| 顺序 | 插件侧 | 宿主衔接 | 验收重点 |
| --- | --- | --- | --- |
| 1. 稳定的学习记录与会话 | 当前Vault下保存问题、引句、材料与草稿；来源版本和AI内容归属明确 | 复用宿主模型传输；显式历史绑定Vault、记录与请求ID | 关闭/重开继续讨论，切换Vault不串数据 |
| 2. A的真实伴读链路 | 右侧追问/想法、正文划选、模型选择、流式显示、取消及重试 | 复用现有AI配置与调用；携带明确的文章/选段上下文 | 从原文真实追问，返回后记录自己的理解；长文显示实际使用范围 |
| 3. 联系已有笔记 | 可查看、移除主动加入的材料；讨论变化有明确提示 | 当前Vault的笔记选择/搜索与读取入口 | 只有所选笔记加入，切文章不静默替换材料 |
| 4. 整理到原生笔记 | 可编辑预览、新建或选择已有关联笔记、来源返回入口 | 原生编辑器插入、撤销、未保存内容与冲突处理 | 新建不覆盖；追加不丢原文或未保存修改，成功后能打开继续编辑 |
| 5. 学习过程的连续性 | 用户草稿及实践结果独立于缓存；维护文件/文章关联 | 文件重命名、Vault切换及异步完成的正确归属 | 清缓存/取消订阅后笔记保留，迟到回复归原记录，失败后能恢复 |

以上首期链路已在插件与宿主代码中实现，持久化及编辑器事务有定向测试；不将模拟AI或浏览器预览视为真实模型与完整原生安装验收。
