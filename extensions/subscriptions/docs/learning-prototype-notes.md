# 学习交互原型：阅读怎样进入追问和笔记

日期：2026-10-19  
状态：用户已选择A「并排伴读」，默认原型已收敛为A。B/C保留为历史对比；代码位于test/learning-prototype，不进入扩展安装包。

要回答的问题：在已有订阅阅读页面中，哪一种呈现最适合让人自然地追问、记录自己的理解，并整理到笔记？

## 启动与入口

在extensions/subscriptions目录执行：

```sh
pnpm prototype:learning
```

打开[已选定的方案A](http://127.0.0.1:4178/?learning-prototype=1&sample=1&variant=A)。默认入口只展示并排伴读，不显示方案切换箭头。

历史比较入口添加`compare=1`，可通过页面底部箭头或左右键循环切换A/B/C，同一页面内的讨论、材料、草稿和演示笔记保持不变。输入框内的左右键正常编辑，批注Tab的方向键正常切换标签。

输入、模拟回复与演示笔记均在内存中，刷新会重置。原型不调用真实AI，不读写真实Vault；原型中的「编辑笔记」也是模拟宿主编辑器的内容交接，尚未对接真实宿主会话或文件。

## 三种不同结构

| 方案 | 使用重点 | 布局与取舍 |
| --- | --- | --- |
| [A：并排伴读](http://127.0.0.1:4178/?learning-prototype=1&sample=1&variant=A) | 阅读时持续追问 | 右侧按需展开讨论与想法，原文可同时阅读；会占用横向空间 |
| [B：就地批注](http://127.0.0.1:4178/?learning-prototype=1&sample=1&compare=1&variant=B) | 围绕当前段落记一句想法 | 小块学习卡插在引用段落后；长讨论会拉长正文，需要验证连续阅读的感受 |
| [C：笔记优先](http://127.0.0.1:4178/?learning-prototype=1&sample=1&compare=1&variant=C) | 集中整理自己的理解 | 阅读区转为主笔记编辑视图，AI按需展开，回到原文继续阅读 |

2026-10-19用户明确选择A。A作为后续实施的主方案，B/C只保留比较证据，不作为三个必须实现的页面。

## 可以实际体验的动作

1. 在正文划选文字，出现「追问」「记想法」。也可用底部「演示划选」选择预置引句，或通过阅读工具条的书本图标重新打开学习。
2. 点击读懂、联系、应用建议，将问题填入输入框，编辑后发送，收到模拟流式回复。
3. 加入演示的《图片缓存方案》等已有笔记，查看明确的材料条目，选择后才参与模拟对照。
4. 直接写自己的想法；无需先发送问题。原文摘录与AI建议由用户主动选入草稿，保留标识。
5. 选择整理到已有或新笔记，先修改预览内容，再模拟追加或创建；已有笔记原内容保留。
6. 在模拟笔记编辑器继续修改；关闭学习、重开及切换方案时，当前页面内的草稿和讨论继续存在。
7. 底部「状态」可以查看本次原型的引句、材料、消息、草稿和演示笔记，确认哪些内容发生了变化。
